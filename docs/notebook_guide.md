# Notebookの操作：準備・質問・確認・保存

Notebookは、説明文とPythonの実行欄（セル）を上から順に読む教材です。セル左側の実行ボタンで、そのセルだけを実行します。`True`は実行する、`False`は実行しないという指定です。全文を理解してから使う必要はありませんが、送信前に自分の質問・資料・会話履歴を確認してください。

## どれを開くか

| Notebook | できること | 使用する計算機 |
|---|---|---|
| 00 準備 | AIなしの説明を保存し、許可された接続を確認 | CPU |
| 01 対話 | 質問や渡す文章を変え、本人の説明を記録 | CPU |
| 02 画像とPDF | 入力する画像・PDFのページを選び、対話と原位置を記録 | CPU |
| 03 公開重みモデル | トークン、数値表現、次の候補、短い応答を観察 | ColabではT4を想定。実機は確認待ち |

[READMEのColabリンク](../README.md#colabで開く)から開きます。大学のGoogleアカウント等でログインし、00〜02はCPU、03は教員の案内に従ってT4を選びます。機種を選べない場合は、TAに状況を伝えてください。現在、Macでの実行と固定版の取得・表示は確認済みで、実際のColabランタイムは未検証です。

## 最初の準備

冒頭の`PREPARE_COLAB`を`True`にして、そのセルを実行します。固定版の教材取得と必要なライブラリの導入を行います。この操作はインターネット接続を使いますが、有料のモデルAPIは呼びません。版の不一致や導入エラーが出た場合は、そのまま次のセルへ進まず、エラーの出たセル番号をTAへ伝えます。

00〜02のAPI送信には、教員が案内した実行設定・送信許可の設定・個別キーが必要です。公開されている空の設定では送信できません。自分で許可済みの印を付けて解除するものではありません。

## 00：AIなしの記録を保存する

「APIなし：個人記録を準備」で`my_explanation`と`my_uncertainty`へ自分の文章を入れます。例えば文字列は`"自分が書いた説明"`のように引用符で囲みます。`None`は前の記入を保持する指定です。`SAVE_OFFLINE_RECORD=True`で保存します。ここまでにAPI料金は発生しません。

## 01・02：質問から保存まで

1. **質問を用意**：`question`へ自分の問いを入力。`conversation_mode='new'`は新しい会話、`'continue'`は成功した会話の続きです。授業の活動は[演習カードの対応表](../activities/day1.md#notebook設定との対応操作時に参照)で確認します。
2. **資料を用意**：01は`source_excerpt`に抜粋、`source_location`に出典位置。02はファイルをColabのファイル欄へアップロードし、`local_path`にそのパスを指定します。`input_kind='image'`ならPNG/JPEG、`'pdf'`ならPDFです。PDFの`pdf_pages`は1始まりの物理ページを、重複なし・昇順で指定します。元の誌面ページと違うときは`page_labels`へ対応を記入します。
3. **送信前の確認**：プレビューセルを実行。質問・抜粋・送る履歴・元ページを確認します。画像やPDFの長いデータは表示だけ省略するので、ファイル自体も開いて確認します。
4. **送信**：許可設定を受け取った後に`SEND=True`。キーは表示・保存しない専用欄へ入力します。この操作からAPI料金が発生し得ます。失敗した場合は自動で再送しません。
5. **本人の説明を保存**：`annotations`に本人の説明、根拠位置、修正、残った疑問を記入し、`SAVE=True`。表示されたJSONLとMarkdownの2ファイルを開いて確認します。AIの生回答は変更せず別に保持します。

次の質問に進むときは、末尾の`START_NEXT_RUN=True`で新しい実行番号を作り、質問・新規/継続・資料・プレビューを確認し直します。同じ送信セルを連打すると、重複送信として拒否されます。新しい実行番号を作っても、前の失敗が取り消されたり、予算が戻ったりするわけではありません。

## 03：モデルの仕組みを観察する

Colabでは冒頭の準備後、必要なライブラリを`INSTALL=True`で導入します。`DEVICE='cuda'`、初回取得時だけ`ALLOW_DOWNLOAD=True`、`LOAD_MODEL=True`で指定モデルを読み込みます。実際の使用機種が表示されたことを確認します。GPUのエラー時にCPUへ自動切替しません。

- `OBSERVE=True`：短い文のトークン・入力埋め込み・続きの候補を表示します。
- `PROMPT`に自分の質問を入れ、`PREVIEW=True`：モデルへ渡す会話テンプレートを表示します。
- `RUN=True`：短い応答を生成。`output_limit`と出たら、途中で上限に達した応答です。
- 自分の説明・不明点を保存セルへ記入し、`SAVE=True`：JSONを保存します。同じ実行の保存済みファイルは上書きしません。

このNotebookはモデルAPIを呼びません。モデル取得とColabの利用枠は別です。このMacのオフライン確認セットでは、案内されたカーネルと`DEVICE='mps'`を使い、`INSTALL=False`・`ALLOW_DOWNLOAD=False`を維持します。

## 閉じる前に手元へ保存する

保存先は、取得した教材フォルダ内の`outputs/`です。00〜02はJSONLとMarkdown、03は`outputs/open-weight/`内のJSONをColabのファイル欄からダウンロードしてください。ランタイムを終了・再起動すると、その中だけに保存したファイルを失う可能性があります。

Notebook本体を保存する場合も、キー・接続情報・個人の対話を含めた公開共有はしません。課題の提出物は指定SlackへのPDFです。ログ原本は自分の手元に残します。[困ったとき](troubleshooting.md)へ。
